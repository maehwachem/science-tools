# 제출 서버 설계

학생이 실험을 마치면 기록이 선생님께 바로 가게 하는 서버입니다. 지금처럼 웨일 클래스에 복사해 붙이는 단계를 없애고, 학생 기기에는 기록을 남기지 않는 것이 목표입니다.

서버는 Supabase 프로젝트 `virtual-science-lab`(서울 리전)을 씁니다. 표와 접근 규칙은 [`schema.sql`](schema.sql) 하나에 들어 있습니다. **아직 서버에 적용하지 않았습니다.**

## 핵심 원칙

- **학생 이름은 서버에 두지 않는다.** 학생은 선생님이 나눠 준 6자리 개인 코드로만 구분합니다. 코드와 이름을 짝지은 명단은 선생님 기기와 선생님이 따로 보관하는 명단 파일에만 둡니다.
- **학생 기기는 내기만 한다.** 학생 기기는 로그인 없이 함수 세 개(`class_info`, `check_member`, `submit_record`)만 부를 수 있고, 표는 읽지도 쓰지도 못합니다. 자기가 낸 기록도 다시 읽을 수 없습니다.
- **선생님은 자기 수업만 본다.** 교사 명단에 있는 계정으로 로그인해야 수업을 만들 수 있고, 자기 수업의 제출만 읽고 지울 수 있습니다. 들어온 제출은 고칠 수 없습니다.
- **기한이 지나면 지운다.** 수업마다 보관 기한(기본 180일)이 있고, 지나면 수업과 제출이 함께 지워집니다.
- **서버가 안 되면 지금 방식으로.** 인터넷이 끊기거나 서버가 멈추면 지금처럼 제출 글을 복사해 웨일 클래스에 냅니다.

## 무엇을 저장하나

| 저장함 | 저장하지 않음 |
|---|---|
| 수업 이름 (예: 2학년 3반 2학기) | 학생 이름, 학번 |
| 6자리 개인 코드 (무작위) | 코드와 이름의 대응표 |
| 실험 기록: 과정 기록, 측정값, 답, 실수 분석, 제출 시각 | 학생 기기 정보 |
| 어느 도구에서 냈는지 | |

Supabase는 서버 운영을 위해 접속 기록(IP 주소 등)을 따로 남깁니다. 개인정보 처리방침에 적어야 합니다.

개인 코드는 학번처럼 짐작할 수 있는 번호가 아니라 무작위 숫자여야 합니다. 학번을 쓰면 학교 안에서는 바로 누구인지 알 수 있어 이름과 다를 것이 없습니다.

## 누가 무엇을 할 수 있나

| | 학생 기기 (로그인 없음) | 선생님 (로그인) | 관리자 |
|---|---|---|---|
| 수업 이름 확인 | 수업 번호를 알면 가능 | 자기 수업 | 전체 |
| 개인 코드 확인 | 맞는지 아닌지만 | 자기 수업 명단 | 전체 |
| 제출하기 | 맞는 코드로만 | 같음 | |
| 제출 읽기 | 불가 | 자기 수업만 | 전체 |
| 제출 고치기 | 불가 | 불가 | 가능 |
| 제출 지우기 | 불가 | 자기 수업만 | 전체 |
| 수업 만들기 | 불가 | 교사 명단에 있을 때만 | 가능 |

관리자는 Supabase 대시보드에 들어갈 수 있는 사람입니다.

## 흐름

### 선생님: 수업 준비 (학기에 한 번)

1. 교사 화면에서 학교 서버에 로그인합니다.
2. 수업을 만듭니다: 수업 이름, 받을 도구, 제출 마감, 보관 기한. 서버가 8글자 수업 번호(예: `K7PX2QMD`)를 만듭니다.
3. 명단(이름)을 넣으면 선생님 기기에서 학생마다 6자리 개인 코드를 무작위로 만듭니다. **서버에는 코드만 올라갑니다.**
4. 코드 쪽지를 출력해 잘라 나눠 주고, 명단 파일(이름·코드)을 내려받아 따로 보관합니다. 선생님 기기를 바꾸거나 잃어버려도 이 파일로 이름을 다시 붙일 수 있습니다.
5. 학생용 주소를 나눠 줍니다. 주소 끝에 수업 번호가 붙습니다. 예: `…/acid-base/virtual.html#c=K7PX2QMD`

한 수업(반·학기)에 여러 도구의 제출을 받을 수 있어서, 학생은 한 학기 동안 같은 개인 코드를 씁니다.

### 학생: 실험과 제출

1. 선생님이 준 주소로 엽니다. 화면에 "2학년 3반 2학기에 제출" 같은 안내가 뜹니다.
2. 이름 대신 개인 코드를 넣습니다. 바로 서버에 확인해서, 틀리면 실험 전에 고칠 수 있습니다.
3. 실험을 마치면 기록이 서버로 갑니다. 성공하면 "선생님께 냈어요", 실패하면 지금처럼 복사해서 내는 화면이 나옵니다.
4. 학생 기기에는 기록이 남지 않습니다.

조별로 하는 도구(환경 대응팀 등)는 조원 코드를 모두 넣고, 한 번 내면 조원 모두의 제출로 남습니다.

### 선생님: 기록 보기

각 도구의 교사 화면(`#teacher`)에서 "학교 서버에서 불러오기"를 누르면, 그 수업에 들어온 그 도구의 제출을 가져와 지금의 분석 화면에 그대로 보여 줍니다. 개인 코드 옆에 선생님 기기의 명단으로 이름을 붙입니다.

### 학기 끝

보관 기한이 지나면 자동으로 지워집니다(예약 작업을 켠 경우). 선생님이 언제든 수업을 지우면 제출도 함께 지워집니다.

## 서버 구조

### 표

| 표 | 내용 |
|---|---|
| `teachers` | 수업을 만들 수 있는 교사 계정. 관리자가 SQL로 넣음 |
| `classes` | 수업: 수업 번호, 이름, 받을 도구, 열림·마감, 보관 기한 |
| `class_members` | 수업별 개인 코드 (이름 없음) |
| `submissions` | 제출: 수업, 개인 코드(조별은 여러 개), 도구, 기록 번호, 기록 내용 |
| `submit_failures` | 틀린 코드로 낸 시각. 코드를 마구 넣어 보는 것을 막는 데만 씀 |

### 학생 기기가 부르는 함수

| 함수 | 하는 일 | 돌려주는 값 |
|---|---|---|
| `class_info(수업 번호)` | 수업 이름과 제출 가능 여부 | 이름, 받을 도구, 열림 여부 |
| `check_member(수업 번호, 코드)` | 실험 전에 코드 확인 | `ok`, `unknown_member`, `closed`, `no_class`, `too_many` |
| `submit_record(수업 번호, 코드 목록, 도구, 기록 번호, 기록)` | 기록 하나 내기 | `ok`, `duplicate`, `unknown_member`, `closed`, `wrong_tool`, `no_class`, `too_many`, `too_big`, `full`, `bad_input` |

- 같은 기록을 두 번 내도 하나만 남습니다 (`duplicate`).
- 한 수업에 틀린 코드가 10분 동안 100번 넘게 들어오면 그 수업은 잠시 제출을 받지 않습니다 (`too_many`). 6자리 코드를 하나씩 넣어 보며 남의 코드를 찾는 것을 막기 위해서입니다. 이때 학생 화면은 복사해서 내는 방식으로 넘어갑니다.
- 기록 하나는 256 KB, 수업 하나는 5000건까지 받습니다.

부르는 방법 (Supabase REST):

```
POST {서버 주소}/rest/v1/rpc/submit_record
apikey: {공개 키}
Content-Type: application/json

{"p_class":"K7PX2QMD","p_codes":["482915"],"p_tool":"acid-base-lab","p_record_id":"mgx1a2b3","p_payload":{…}}
```

### 도구 이름

`acid-base-lab`(산·염기 가상 실험실), `redox-lab`(산화·환원 가상 실험실), `env-team`(환경 대응팀), `battery-team`(배터리 시험팀), `battery-lab`(배터리 가상 시험동), `chemists-island`, `chem-voyage`, `solution-lab`

## 적용 순서 (관리자)

1. **표 만들기:** Supabase 대시보드 → SQL Editor에서 `schema.sql`을 실행합니다. 여러 번 실행해도 됩니다.
2. **가입 막기:** Authentication → Sign In / Providers에서 새 사용자 가입을 끕니다. 교사 계정은 관리자만 만듭니다. (가입을 열어 두더라도 교사 명단에 없는 계정은 수업을 만들 수 없습니다.)
3. **교사 계정:** Authentication → Users → Add user로 이메일·비밀번호 계정을 만들고, SQL Editor에서 교사 명단에 넣습니다.
   ```sql
   insert into public.teachers (id, name)
   select id, '선생님 이름' from auth.users where email = '선생님 이메일';
   ```
4. **자동 정리 (선택):** Database → Extensions에서 `pg_cron`을 켜고 `schema.sql` 맨 아래 주석의 한 줄을 실행합니다.
5. **사이트 설정:** 서버 주소와 공개 키(Project Settings → API Keys의 publishable 키)를 사이트 공통 설정에 넣습니다. 공개 키는 원래 공개되는 값이고, 보호는 위의 접근 규칙이 맡습니다.

주의: 무료 요금제는 한동안 쓰지 않으면 서버가 일시 정지될 수 있습니다. 방학 뒤에는 대시보드에서 다시 켜야 할 수 있습니다.

## 앱별로 바꿀 점

| 순서 | 도구 | 바꿀 점 |
|---|---|---|
| 1 | 공통 교사 도구 (새로 만듦) | 로그인, 수업 만들기, 명단·개인 코드·쪽지, 명단 파일, 학생용 주소 |
| 2 | 산·염기 가상 실험실 (시범) | 이름 칸 → 개인 코드, 시작 전 코드 확인, 마치면 서버로 내기, 교사 화면에 서버에서 불러오기 |
| 3 | 산화·환원 가상 실험실 | 같음 |
| 4 | 환경 대응팀 | 조원 이름 → 조원 코드, 결과 파일 대신 서버로 내기 |
| 5 | 배터리 시험팀·가상 시험동 | 같음 |
| 6 | 화학자의 섬·항해, 용액 조제실 | 이미 있는 명단·개인 코드를 서버의 개인 코드와 맞춤 |

모든 도구에서 서버로 보내는 기록에는 이름이 들어가면 안 됩니다. 이름 칸은 개인 코드로 바꾸고, 조별 모드의 조원 이름도 코드로 바꿉니다. 서술형 답에는 "답에 이름을 쓰지 마세요" 안내를 넣습니다.

claude.ai에서 여는 원본 도구는 수업 번호가 없으니 지금처럼 복사해서 냅니다.

## 학교 확인용 요약

- **목적:** 수업 중 가상·실제 실험 기록을 선생님께 제출
- **수집 항목:** 6자리 개인 코드(무작위, 이름 아님), 수업 이름, 실험 과정·측정값·답, 제출 시각. 서버 운영 업체의 접속 기록(IP 등)
- **이름과 코드의 대응표:** 교사 기기와 교사가 보관하는 파일에만 있음. 서버에 저장하지 않음
- **열람:** 그 수업 담당 교사만. 학생은 내기만 하고 읽을 수 없음
- **보관 기간:** 수업별 기한(기본 180일) 뒤 자동 삭제. 교사가 언제든 삭제 가능
- **저장 위치:** Supabase(미국 회사)의 서울 리전 서버

코드만 저장해도 선생님이 명단으로 다시 누구인지 알 수 있으므로, 법적으로는 가명정보(개인정보의 한 종류)로 다뤄질 수 있습니다. 최종 판단은 학교 개인정보 담당자에게 확인합니다.

## 시험

로컬 PostgreSQL 16에 Supabase의 역할(`anon`, `authenticated`), 기본 권한, `auth.uid()`를 흉내 내어 `schema.sql`을 적용하고 43가지를 확인했습니다. 모두 통과했습니다.

- 학생 기기: 표 다섯 개 모두 읽기·쓰기 막힘, 제출 직접 넣기 막힘, 정리 함수와 수업 번호 함수 실행 막힘
- 선생님: 자기 수업만 보임, 남의 수업에 코드 넣기 막힘, 교사 명단 밖 계정의 수업 만들기 막힘, 제출 고치기 막힘, 제출 지우기 가능
- 제출: 정상 제출, 중복, 틀린 코드, 조별 제출, 조원 중 틀린 코드, 잘못된 도구 이름·기록 번호, 256 KB 초과, 받을 도구 제한, 닫힌 수업, 마감 지남, 틀린 코드 100번에서 잠김(99번까지는 정상)
- 정리: 보관 기한 지난 수업이 제출·코드와 함께 지워짐
- `schema.sql`을 두 번 실행해도 오류 없음
